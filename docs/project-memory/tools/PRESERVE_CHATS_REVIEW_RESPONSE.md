Review: `isalwa-review-evidence/INDEPENDENT_REVIEW_20261016-192946/SECURITY_REVIEW_preserve_chats/SECURITY_REVIEW.md` (reviewed blob `b34a6662…`, sha256 `185a2379…f625d`).

**The script has not been run over real chat sources.** Tests use synthetic fixtures only: `test_preserve_chats.py`, 19/19 passing.

| Finding / requirement | Change |
|---|---|
| S1: hashes of unredacted blocks | The payload carries no hash of any unredacted block. Original hashes go only to `<staging>/local-restricted/ORIGINAL_HASHES.csv`, which is never transferred. The `sha256_16` column of `USER_TURN_COVERAGE.csv` is dropped from the project-memory copy. In a redacted project-memory file, `sha256 (original…)` values are replaced. The manifest hashes final payload files only. Test: `test_no_original_hash_in_payload_and_restricted_record_kept_local` |
| S2: personal data | Added: Bolivian numbers with context words (celular, teléfono, WhatsApp, móvil, número), CI/carnet/NIT numbers, international numbers. Names, businesses and addresses can't be detected by machine. `review/REVIEW_REQUIRED.csv` therefore lists line numbers for residual 7–10-digit numbers, personal-context words and long hex values, plus a mandatory human-review row. The payload is labelled "redacted (regex), NOT REVIEWED" and `STATUS.json` sets `backup_ready: false` |
| S3: token gaps | Whole-token character class `[A-Za-z0-9._-]`. JWT (all three parts), `sk-proj-`, `sk-ant-`, `EAA…`, `sb_secret_`/`sb_publishable_`, Mapbox `sk.`/`pk.eyJ…`, AWS, Twilio `AC`/`SK`, GitHub/GitLab/Slack/Stripe/npm/Shopify prefixes, bearer tokens. `*_KEY`/`TOKEN`/`SECRET`/`PASSWORD`/`DSN`/`DATABASE_URL` assignments, with code expressions excluded. A high-entropy rule for mixed-case values after `=`/`:`. Prefixes that also start ordinary identifiers (`re_`, `sk-`, `EAA`…) need a long mixed-case value with digits |
| S4 / required 1: destination | `--staging` must not exist. Its parent must exist, every path component must be free of symlinks, and the path must sit inside an explicit `--allowed-root`. Refused: `~/.cursor`, `~/Library`, the repository, the projects root, the memory dir, `/`, `$HOME`, and paths containing `.`/`..`. The script creates the directory itself (0700). All writes go through `Staging.write`: path-traversal check, `O_CREAT\|O_EXCL\|O_NOFOLLOW`, no overwrite. No `rmtree` and no deletion anywhere. Symlinked sources are refused (`O_NOFOLLOW`). Tests: existing staging refused and untouched; symlinked parent; outside root and forbidden roots; write-once and traversal; symlinked source |
| S5 / required 5: partial failure | Every item error is collected (transcript, index row, subagent, screenshot, mixed line, project-memory file) and the run continues. `COVERAGE.md`/`COVERAGE.csv` list each one. A COMPLETE run is renamed to `payload/`; anything else to `payload.INCOMPLETE/` with exit 2. `MANIFEST.sha256` covers exactly the files this run wrote, excluding itself. Tests: missing transcript; invalid chat id; manifest exactness |
| C1 / required 3: attribution | One segment per user event. Agent text belongs to the segment of the user event before it. Repeated prompts are kept and marked with the line of the first occurrence. Agent text after context or system events, or before the first user event, is labelled "boundary ambiguous; not attributed to a prompt". Tests: `test_attribution_keeps_ambiguous_boundaries_and_repeats`, `test_chat_file_marks_ambiguous_text` |
| C2 / required 4: measured coverage | Per chat: prompt hashes produced vs `USER_TURN_COVERAGE.csv` (missing and extra listed individually); subagent files found vs `CHAT_INDEX`, and each subagent with both task and report text; referenced screenshots cleared and copied. Any mismatch → chat INCOMPLETE. Tests: index mismatch; empty subagent report; uncleared screenshot |
| C3: dates and ids | The generic number rule is removed. Phones need `+` or a context word. Test: ISO dates, timestamps, UUID chat ids, 8-hex chat prefixes, commit SHAs, `git@` remotes, private IPs and code identifiers stay intact |
| C4: attribution statement | Kept, and states that relayed customer words are not separately marked |
| I2 / required 6: CCA | A prompt where CCA/Rose terms are ≥3 and outnumber ISALWA mentions is **withheld** together with its replies, and recorded in `local-restricted/OMISSIONS.csv`. The chat becomes PRESERVED_WITH_OMISSIONS (hold). Every payload file is also scanned for CCA/Rose keywords and the hits are listed for review. Mixed chats: listed lines only |
| I5: id validation | `chat_id` must be a UUID and the project a single safe component, otherwise the item errors |
| I6 / required 6: project-memory copies | Redacted with the same rules; hash columns dropped as above |
| Required 7: review before transfer | `review/REVIEW_REQUIRED.csv` (no values) plus a human review of the actual payload, recorded before any upload. No secret values are printed |
| Required 8: omissions keep hold | Any redaction or withheld block → PRESERVED_WITH_OMISSIONS. Only PRESERVED_LOSSLESS chats in a COMPLETE, reviewed, uploaded and remotely verified payload can be proposed for deletion. Test: `test_chat_without_omissions_is_lossless` |

Limits: the redaction's effectiveness on real data is unmeasured until the gated run and the human review. Customer names, businesses and addresses rely on that review. Python 3.9.6 is the target interpreter (`Path.is_relative_to` is available).
